The Polish raw increase is spike-sensitive. On 2026-08-12, the selected Polish basket had 71,281 pageviews; the solar-eclipse article led it. A date-and-keyword web search found independent descriptions of the August 12 solar eclipse from [NASA](https://science.nasa.gov/eclipses/future-eclipses/total-solar-eclipse-on-august-12-2026/) and the [Polish Space Agency](https://polsa.gov.pl/wydarzenia/coz-to-bedzie-za-wieczor/). Both match the date and subject. This is a plausible explanation, not proof of referral cause or reader location. The event is partial in Poland, while totality is elsewhere.

The 2025-09-07 spike is a useful negative case: date searches find a **lunar** eclipse ([UMCS](https://www.umcs.pl/pl/calkowite-zacmienie-ksiezyca-nad-lublinem-7-wrzesnia-2025r%2C33504.htm)), while the map's leading QID is **solar** eclipse. A matching date alone is not enough to assign that event as the cause; this map leaves it unverified.

## OpenRouter small-model check

Models: `openai/gpt-oss-20b` and `google/gemini-2.5-flash-lite`. Both received the same compact live map and dated search-result fixture, including a synthetic distractor. Two cases were tested: a corroborated 2026-08-12 eclipse, and an uncorroborated 2025-09-07 spike for which only wrong-date solar-eclipse sources were supplied. The rubric checks JSON validity, date/topic matching, source selection, reader-country restraint, rounded growth values, peak sensitivity, and causal restraint. Full outputs and usage: `topic-map-openrouter-2026-09-26.json`. `OPEN_ROUTER_API_KEY` was loaded into the process environment through `python-dotenv`; its value was not printed or stored.

| Model | Corroborated, baseline → clearer prompt | Uncorroborated, baseline → clearer prompt |
|---|---:|---:|
| gpt-oss-20b | 5/9 → 9/9 | invalid response → 5/5 |
| gemini-2.5-flash-lite | 5/9 → 9/9 | 1/5 → 2/5 |

Prompt changes improved both models on the corroborated case and GPT-OSS-20B on the uncorroborated case, but did not reliably stop Gemini's unsupported explanation in the latter. GPT-OSS-20B also returned an invalid baseline response in one case; an additional attempted batch was interrupted after a long stalled response and is excluded from the scores. These are single completed calls per variant, so the scores are scenario checks, not general model accuracy estimates.

The implemented deterministic `verify-spike` gate now rejects wrong dates, wrong leading QIDs, duplicate hosts/publishers, and non-HTTPS source metadata. In the two fixtures, a guarded output passed 9/9 and 5/5 structural/factual checks respectively. **Those guarded scores measure the gate, not the model.** The agent still has to inspect each source; the gate cannot prove article contents or traffic causation. When evidence is insufficient, the agent must report `unverified` regardless of model wording.
