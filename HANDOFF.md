# Передача роботи: робочий MVP

## Оновлення 26 вересня 2026 року

Додано команду `map` для кураторської мапи 2–12 Wikidata QID у 1–6 мовних версіях Wikipedia. Вона зберігає прогалини sitelink, динаміку підтематик і всього вибраного кошика, нормалізацію за трафіком розділу, перевірку пікового місяця та кандидатні дати сплесків. `SKILL.md` тепер вимагає змістовного висновку агента за мапою й пошуку датованих пояснень сплесків. Команда `verify-spike` перевіряє метадані незалежних джерел перед тим, як назвати пояснення правдоподібним. Це не доводить причинність і не замінює перегляд джерел агентом.

Живий двомовний приклад і оцінювання двох малих моделей OpenRouter записано в `evaluation/topic-map-2026-09-26.md`. У короткому тесті ясніший промпт не усунув усі хибні пояснення, тому правило безпечного висновку має спиратися на детерміновану перевірку. Зараз проходить 41 автоматизований тест. Наведений нижче розділ описує історичний стан MVP на 25 вересня.

Роботу відновлено 25 вересня 2026 року. MVP реалізований, технічні перевірки пройдені. Незалежне оцінювання недорогої моделі завершено з одним зафіксованим провалом поведінкового критерію: модель безпідставно заявляла, що візуально переглянула PDF. Тому повне приймання поведінки моделі **не пройдене**. Деталі й докази: `evaluation/cheap-model-2026-09-25.md`.

## Що вже працює

Усі вихідні матеріали розташовані в директорії `wikipedia-opportunity/`:

- `SKILL.md`: самостійна навичка Agent Skills із коротким сценарієм для агента.
- `scripts/wiki_interest.py`: команди `discover`, `plan`, `run`, `reanalyze`.
- Пошук тем через Wikidata, зіставлення мовних статей за QID, перевірка існування, перенаправлень і неоднозначних назв.
- Завантаження денних переглядів статей та загального трафіку мовного розділу. Відсутні суміжні місяці завантажуються одним запитом; індекси місяців посилаються на оригінальні відповіді API.
- Кеш, перевірка хешів, обмежені повторні спроби, офлайн-режим, незмінні версії досліджень та повторний аналіз критеріїв без мережі.
- Порівняння двох повних річних періодів: абсолютне зростання, зміна частки в трафіку мовного розділу, перевірка впливу пікового місяця, концентрація переглядів у найбільші сім днів, повнота даних.
- Графік PNG, таблиця CSV, JSON із розрахунками й походженням даних, Markdown і односторінковий PDF.
- Відтворюване Python-середовище: `requirements.txt` та повний `requirements.lock`; вихідний код без скомпільованих виконуваних файлів у пакеті.
- Методологія, формат вхідних даних, план розвитку й інструмент для окремого оцінювання через OpenRouter.

## Що перевірено

- **37 автоматизованих тестів пройшли.** Перевірені розрахунки, пропуски/нулі, сплески, мала база, кеш, API-помилки, зіставність кошиків статей, цілісність snapshot, PDF, provenance, автоматичні критерії оцінювання й межі файлових операцій тестового агента.
- Валідація `SKILL.md` пройдена; `pip check` не виявив конфліктів залежностей.
- Живі контрольні дослідження кількох мовних версій Wikipedia за 2024-09-01 — 2026-08-31 виконані. Історичні дані та звіти збережено в `examples/`; вони не задають тему для нових запитів.
- Новий український сценарій із порожнім кешем потребував **4 HTTP-запити**. Усі аналітичні значення збіглися з попередньою реалізацією, яка завантажувала місяці окремо.
- Повторний аналіз із порогом 30% працює без мережі. Перевірено односторінковий PDF, кирилицю, графіки й таблицю; виконано візуальний перегляд українського, двомовного та синтетичного шестирядкового звітів.
- Відсутня польська відповідність для Q1666254 коректно зупиняє планування; відсутність статті не перетворюється на нульовий попит.
- У `provenance.json` схеми 2 розділено первинне отримання даних (`source_acquisition`) і поточний запуск (`current_run`). Міграцію старої схеми 1, новий запуск і повторний `reanalyze` перевірено тестами.
- Недорога модель `gpt-5.6-luna` виконала основний сценарій, зміну порога 10%→30% без мережі та сценарій відсутнього sitelink. Числа, період і обережність висновку пройшли ручну перевірку. Три непідтверджені заяви про візуальний огляд PDF не пройшли критерій 4. Один початковий висновок виправлено після фактичного показу зображення моделі.

Деталі й точні результати: `evaluation/results.md`.

## Відкритий критерій і необов'язкова перевірка

- Для повного приймання на недорогій моделі потрібен новий **перший** запуск, де відповідь або справді спирається на показане моделі зображення PDF, або чесно повідомляє, що візуальний перегляд недоступний. Збережене оцінювання має результат «fail» за критерієм 4; автоматизовані тести коду не можуть змінити цей висновок. OpenRouter/Haiku не перевірялися: `OPENROUTER_API_KEY` не було. Токени, вартість і затримка не виміряні.
- Чисту інсталяцію з фінального архіву перевірено на macOS arm64/Python 3.12; окрема перевірка на Linux лишається бажаною, але середовище Linux наразі недоступне. Вона не є умовою запуску цієї навички на перевіреній платформі.

## Подальший розвиток після MVP

Це покращення наступних ітерацій, а не вже реалізовані можливості:

- Повна історія перейменувань, створення статей і трафіку перенаправлень; зараз аналізується поточна назва, а перевірка журналу переміщень неповна.
- Кураторські кошики для складних тем і вузького наміру; агент має обґрунтовувати вибір проксі.
- Сезонні моделі, контрольні теми, подієві вікна й належно обґрунтовані оцінки невизначеності. Поточні сигнали — описові евристики, не статистична впевненість.
- Українські та інші мовні шаблони PDF, складні системи письма/RTL. Наразі аналітичні підписи англійські; кирилиця підтримується.
- Масштабування понад шість рядів/шість статей на ряд: SQLite/Parquet, обмежений паралелізм, стійкі черги, відновлення довгих досліджень.
- Розширений набір сценаріїв оцінювання недорогих моделей і CI для кількох платформ.

Порядок і критерії приймання кожної ітерації: `references/development.md`.

## Як продовжити

Команди виконуються з директорії навички, використовуючи Python 3.12+:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m pytest -q

.venv/bin/python scripts/wiki_interest.py run \
  --config work/plan.json --out work/my-study

.venv/bin/python scripts/wiki_interest.py reanalyze \
  --run work/my-study --criteria examples/criteria-strict.json --out work/my-study-strict
```

Вихідні директорії мають бути новими. `.venv/`, `.cache/`, `work/` та байткод не включаються до пакета навички.

## Окрема примітка про Claude CLI

До забороненого корпоративного акаунта не було жодного запиту генерації. Було виконано спроби виходу й прибрано кешовану ідентифікацію акаунта, але повне відкликання авторизації підтвердити не вдалося: CLI продовжував показувати `loggedIn: true`, а доступ через Keychain Access не був дозволений. Перед будь-яким подальшим використанням Claude CLI власнику потрібно вручну перевірити вихід і дозволений акаунт. Це не є залежністю навички або її Wikimedia-коду.
